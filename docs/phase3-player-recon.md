## Как устроен плеер сейчас (факт)

**Точка входа:** `client-nuxt/app/pages/quest/[slug].vue` (672 строки).
Грузит квест по slug, проверяет код доступа (`access_code` → 403/POST access),
управляет состоянием прохождения (blockIdx, completedIds, points, таймер).

**Выбор версии плеера:**
```js
const playerVersion = computed(() => questData.value?.player_version || 'v1')
```
В шаблоне ДВЕ реализации, переключаются по `playerVersion`:
- **V1** — инлайн прямо в `[slug].vue` (`v-if playerVersion === 'v1'`): HUD,
  блоки, навигация, splash, ввод кода. Это БОЛЬШАЯ часть 672 строк.
- **V2** — отдельный компонент `QuestPlayerV2.vue` (358 строк),
  `v-if playerVersion === 'v2'`.

**❗ Ключевой факт:** в БД (`database/dump.sql`) у ВСЕХ 9 шаблонов
`player_version = 'v1'`. Значений `v2` — НОЛЬ. То есть **V2 нигде не
используется**, рендерится только V1.

## Типы задач (рендерятся в `QuestTask.vue`)

5 типов, по `task.type`:
- `simple` — найди подсказку (текст)
- `riddle` — загадка (вопрос + ответ)
- `selfie` — сделать селфи (камера `capture="user"`, фото-зона)
- `text_answer` — текстовый ответ
- `mini_game` — мини-игра, ветвится по `game_type`:
  - `quiz` — викторина (в данных: 8 шт)
  - `pairs` — найди пары (в данных: 4 шт)
  - `puzzle` — пазл (**в коде есть, в данных 0 — мёртвая ветка**)
- `photo` — есть отдельная ветка (`capture="environment"`), проверить
  отличие от `selfie`

## Расхождения плана Фазы 3 с реальностью

**3.1 «Удалить иммерсивный плеер»** — план предполагает, что иммерсивный
(вероятно V2?) — основной, базовый — запасной. По факту НАОБОРОТ: V1
основной (все данные на нём), V2 не используется вообще. Развилка:
- либо V2 — это и есть «иммерсивный», который хотели убрать → удаляем V2,
  чистим `player_version`-логику, остаётся один V1 (его и редизайнить);
- либо V2 — недоделанная «новая» версия, которую хотели сделать основной →
  тогда решать, доделывать V2 или редизайнить V1.
  **Нужно решение владельца ДО кода.**

**3.2 «Аудит мини-игр, особенно с фото»** — актуально. Фото-механики:
`selfie` (фронт-камера), `photo` (тыловая камера), `pairs` (возможно
картинки). Проверить на мобиле: соотношения, обрезка, lazy-load, превью.
`puzzle` — мёртвая ветка в коде, кандидат на удаление (в данных нет).

**3.3 «Первый реальный сценарий»** — контентная задача, не код. Не
блокируется редизайном.

## Инструменты (договорённость)

- **Claude Code** — основная среда (читает репо, правит, тестирует, коммитит).
- **Playwright MCP** — браузерная обратная связь по фронту (то, чего не
  хватало: видеть рендер без деплоя). Один браузерный MCP достаточно.
- НЕ нужны под эту задачу: firecrawl/perplexity (веб-скрейпинг — не про свой
  код), glif (генерация медиа — пригодится в 3.3, не сейчас), Chrome MCP
  (дублирует Playwright).

## Рабочие правила проекта (напоминание для Claude Code)

- Ветка от `production`, PR, зелёный CI перед merge.
- **Фронт-тестов в CI НЕТ** (client-зона) — проверка ручная/через Playwright.
- Серверные правки — под unit+integration (реальная PostgreSQL, testcontainers).
- Деплой: `git pull && docker compose build client && up -d` на VPS.
- Бэкенд на хосте: docker пробрасывает `server:5000` → `localhost:5001`,
  БД → `localhost:5433`, фронт → `localhost:3000`.
- Прод = стенд (клиентов пока нет), но дисциплина: маленькие PR, проверка
  после каждого деплоя.
