## Стратегия

1. **Сначала фундамент.** Пока в коде есть P0-уязвимости и мокированные тесты,
   любая продуктовая фича рискует сломать прод или утечь данными.
2. **Потом главная фича.** AI-опросник через DeepSeek — единственное реальное
   конкурентное преимущество, важнее редизайна.
3. **Потом продукт.** Редизайн плеера, сценарии с фото, аудит мини-игр — это
   делается после того, как опросник стабильно работает и даёт нормальные данные.

## Фаза 2 — AI-опросник через DeepSeek

Цель: заменить статичную форму заказа на интерактивный AI-диалог,
который собирает данные и **автоматически заполняет шаблон квеста**.

### 2.1. Требует brainstorm с Claude

Открытые вопросы для проработки через `/brainstorming`:

1. **Какие поля шаблона квеста заполняет AI?**
   - Сейчас структура `quest_template.fields` — какая она?
   - Какие данные клиента нужны для уникализации (имена, локации, фото партнёра,
     общие воспоминания, любимые места, дата знакомства, инсайды)?

2. **Как AI ведёт диалог?**
   - Фиксированный сценарий вопросов или адаптивный?
   - Сколько вопросов? Можно ли пропускать?
   - Что делать, если клиент даёт мусорные ответы?

3. **Где запускается DeepSeek — фронт или бэк?**
   - Лучше: бэк (защита API-ключа, логирование, rate limiting)
   - MCP-подключение Claude Code для разработки vs production-вызовы

4. **Архитектура UX:**
   - Заменяем `order/[templateSlug].vue` или это новая страница `order/[templateSlug]/ai`?
   - Сохранение прогресса при потере соединения
   - Как клиент видит "что AI понял" перед оплатой

5. **Валидация результата:**
   - AI заполнил поля → клиент видит превью → подтверждает
   - Admin потом может править результат вручную

### 2.2. Архитектурный скелет (черновой)

```
client-nuxt/app/pages/order/[templateSlug]/ai-chat.vue   ← новый UI
client-nuxt/app/composables/useAiQuestionnaire.js        ← логика диалога
server/src/routes/ai.js                                  ← /api/ai/chat
server/src/services/deepseekService.js                   ← DeepSeek API
server/src/services/questGeneratorService.js             ← парсит ответ → fields
database/migrations/add_ai_conversations.sql             ← хранение истории
```

### 2.3. Этапы

- **2.3.1.** Brainstorm: спецификация полей и сценария
- **2.3.2.** Backend: `/api/ai/chat` endpoint, DeepSeek-интеграция
- **2.3.3.** Backend: парсер ответа AI → `quest_template.fields`
- **2.3.4.** Frontend: чат-интерфейс на `/order/[templateSlug]/ai-chat`
- **2.3.5.** Сохранение истории разговоров в БД
- **2.3.6.** Admin: возможность править результат AI
- **2.3.7.** A/B-тест: старая форма vs AI (опционально)

## Правила работы

1. **Каждая задача — отдельная ветка** от `production`, имя `upgrade/<short-name>`
2. **TDD где возможно:** сначала тест, потом код (используем GSD-подход)
3. **Маленькие коммиты:** один логический шаг = один коммит
4. **Перед мержем в `production`:** CI зелёный + ручная проверка
5. **После мержа:** деплой через `docker compose build && up -d` на VPS
6. **Аудит обновляется:** закрытые пункты помечаются как done
